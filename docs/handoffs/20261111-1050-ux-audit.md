### 0.3 三条跨旅程根因

1. **技术对象直接变成了导航和文案。** 首屏和第二层页面大量出现 Ubuntu、Node.js、DSH、WebView、PRoot、SHA-256、loopback、workspace-write。用户要的是「让 AI 读写我的项目」，不是「安装一个 Linux 发行版」。技术词可以作为详情，但不能作为主标题和主按钮。
2. **状态与动作分离。** 进度、错误、成功提示各自只挂在某一个页面：安装失败只在工作台底部；DSH 崩溃的恢复卡只在工作台；远程断开只在设置页状态卡；导入完成只在事件日志里。用户切一次页，信息就丢了。
3. **没有「下一步」闭环。** 导入完成后不跳到新项目；远程连接成功后不跳到 DSH；更新检查完不落到更新卡；崩溃后当前页只能看错误详情，没有恢复动作。每个动作结束，用户都要自己猜下一步去哪。

### 1.2 摩擦点：用户会怎么想错

**F1.1 「这是干什么的」没有被回答。**
首屏第一句是「让开发环境，随灵感就位。」这是品牌文案，不是产品说明。用户看不到：这个 App 能在手机上做什么、项目存在哪、要不要 Root、要不要联网、要不要账号、模型请求发给谁。一个普通用户会把它当成「又一个终端模拟器」或「又一个聊天壳」，不知道为什么要先装 Linux。

**F1.2 不知道为什么先装 Ubuntu 和 Node.js。**
步骤标题只有对象名和一句技术说明：「提供 DSH 所需的 Linux 系统与基础目录」「为 DSH 提供 JavaScript 运行环境」。用户会想：「我只是想跟 AI 聊天，为什么要装操作系统？」没有一句话解释「AI 要执行命令、读写文件，所以需要一个隔离的 Linux 环境」。

**F1.3 没有开始前准备清单。**
当前只有进到安装里才会遇到：需要网络；`ensureBase` 才检查「至少 1.5GB，建议 4GB」；WebView 不支持 123+ 时，装到一半才在顶上出现升级卡；模型 API Key 完全没提。用户会在最不适合的时刻（已经等了十几分钟）发现还缺东西。

**F1.4 第一次确认框就出现「请先停止 DSH」。**
首次安装 Ubuntu 的确认文案结尾是「请先停止 DSH。」但此时 DSH 还没安装、也没运行。用户会以为后台有任务在跑，或者以为自己点错了。

**F1.5 每一步都要手动「下一步」，完成态没有反馈。**
组件装完后，当前步骤仍然是当前步骤，只是按钮变成「已安装」；没有「✓ 已完成，继续」的明确引导，也没有自动把焦点移到下一步。用户会停在原地，怀疑是不是没装好。步骤条有「1 / 4」，但没有总时长/总进度。

**F1.6 最快路径被藏起来了。**
一键准备在第 2 个 Tab 的空态里，而首屏是分步向导。普通用户会走 12 次点击的路径，而不是 4 次的那条。

**F1.7 WebView 是隐藏的前置条件。**
只有 `WebViewSupportState.UPDATE_REQUIRED` 时，首屏顶部才出现「升级 WebView，打开 DSH」。它不阻止 Ubuntu/Node 安装，用户可能装完前两步才发现 DSH 打不开，还要去外部商店升级内核。

**F1.8 没有「我已经装过 / 从备份恢复」入口。**
重装应用、换机、恢复快照的用户也被当成新用户，从第 1 步开始。设置里的「私有快照」入口在第 3 层，首屏没有提示。

**F1.9 「稍后再说」没有定义。**
用户按返回键会直接退出应用，安装如果已经在跑则退到后台；页面没有说「可以稍后继续，进度在通知栏」。用户不敢离开。

### 1.3 建议改法

**R1.1（P0）首启加一屏「开始前」说明。**
- 页面/位置：工作台首帧，品牌区下方、步骤条上方；首次安装且未完成时显示一次。用全宽卡片或半屏 `ModalBottomSheet`，不要挡住「开始准备」。
- 标题：**「先花 1 分钟，了解 Tanuki 能做什么」**
- 正文三条：
  1. 「Tanuki 在你的手机里运行一个独立的开发工作台：AI 可以读写项目文件、执行命令，不需要 Root。项目和运行环境都在本机；模型请求会发送到你选择的 API 服务商。」
  2. 「第一次使用需要联网下载 Ubuntu、Node.js 和 DSH。至少预留 1.5 GB 空间（建议 4 GB），通常需要十几分钟，取决于网络。」
  3. 「装好后还要在 DSH 里填入你自己的模型 API Key，才能开始对话。」
- 按钮：主按钮 **「开始准备（推荐）」**；次按钮 **「分步安装，我自己选版本」**；文字按钮 **「稍后」**。
- 关闭后不重复弹；在「设置 → 关于与诊断」加一行 **「查看新手引导」** 可重看。
- 验收：新安装首次进入，5 秒内能说出「这是干什么的、要准备什么、装完还差什么」。

**R1.2（P0）把一键准备提到首屏主按钮。**
- 页面/位置：工作台首屏，步骤条下方第一张卡。

## 2. 安装运行环境 / DSH：进度、失败、等待

### 2.1 现状步骤与反馈

| 阶段 | 用户看到 | 评价 |
|---|---|---|
| 下载 Ubuntu/Node | 组件卡内：来源、百分比、已下载/总量、速度、预计剩余；顶部操作条：阶段名、已用时间 | 有真实进度，不伪造百分比，合格 |
| apt 补工具 | 阶段文字 + 「当前安装阶段 X%」，并注明「不代表整个安装已完成」 | 诚实，但百分比含义需要读小字才懂 |
| 安装 DSH | 不定进度 + 已用时间 + 「解析、校验与安装无法准确估算总量」 | 诚实，但用户容易怀疑卡死 |
| 后台 | 前台服务通知显示进度 | 存在，但用户不知道 |
| 失败 | 工作台底部「需要留意」卡，展开「查看错误信息」 | 不可就地恢复，且离开工作台就看不到 |
| 成功 | 组件卡变「已安装」/ 自动进入 Ready 工作台 | 成功反馈弱，没有「下一步」 |

### 2.2 摩擦点

**F2.1 没有「现在在做什么、还剩几步」的总览。**
用户看到的是长句阶段名，例如「安装官方 DSH 0.2.1-rc.5（锁定入口版本，保存依赖锁）」「解析、校验与安装无法准确估算总量」。普通用户无法把它映射成「下载 → 校验 → 安装 → 启动检查」四步，也不知道现在在第几步。

**F2.2 失败后没有「就地恢复」按钮。**
下载失败时错误只出现在页面最底部；组件卡里的安装按钮恢复成「安装 Ubuntu」，但用户不知道这是重试还是重装。错误提示里写「请检查网络或切换下载源」，却没有「切换下载源」按钮；写「空间不足」，却没有「清理缓存」按钮。

**F2.3 离开工作台后，失败完全静默。**
`OperationBanner` 只在 `operationActive` 时显示；失败后 `operationActive` 变 false，banner 消失。`OperationCard` 只挂在 Setup/Ready 工作台和 DSH 空态；用户在文件页、浏览器页或设置页时，安装失败没有任何提示。用户会以为还在装。

**F2.4 没有开始前的体积/时间预期。**
Ubuntu 与 Node 的版本选择器里有大小（约 28 MB / 55 MB），但首屏和确认框没有汇总；DSH 依赖与基础工具的大小完全未知。用户不知道要等 2 分钟还是 30 分钟。

**F2.5 等待时能做什么没有说明。**
没有一句话告诉用户「可以切到其他应用/锁屏，安装会继续；进度在通知栏」。用户要么盯着进度条，要么不敢离开。

**F2.6 取消后的状态不明确。**
组件卡里是「取消下载」，顶部进度弹窗里是「取消当前操作」；取消后阶段文字写「已取消，可重试并复用完整下载」，但组件卡本身没有恢复提示，用户不知道缓存还在不在。

**F2.7 通知权限申请没有理由。**
点安装时突然弹系统通知权限。用户不知道为什么一个装环境的 App 要通知权限；拒绝后，后台进度和失败提醒都看不到。界面没有解释「允许通知后，锁屏也能看到安装进度」。

**F2.8 60 秒无进展的提示不够显眼。**
顶部操作条在 60 秒后会显示一句「X 秒没有新进展，点“查看进度”了解状态」，但组件卡本身没有提示；完整解释还要打开弹窗。用户容易反复点按钮或强杀应用。

**F2.9 自动换源是黑盒。**
下载失败自动换源时，界面只显示新的 source 名，没有「刚才那个源失败了，已换到 X」的说明。用户不知道是网络问题还是应用在乱跳。

**F2.10 WebView 失败路径没有出口。**
「去升级 WebView」会跳到应用商店或系统 WebView 设置；如果设备没有商店或无法升级，用户只知道 DSH 打不开，不知道还能不能继续用文件/浏览器，也不知道环境是否白装。

### 2.3 建议改法

**R2.1（P1）安装总览改成 5 段式 stepper。**
- 页面/位置：安装进度卡顶部。
- 五段：**「下载 Ubuntu」→「准备 Linux」→「安装 Node.js」→「补齐工具」→「安装并检查 DSH」**；当前段高亮，完成段打勾。
- 当前段下面保留现有的真实字节进度/不定进度与「已用 X 分 Y 秒」。
- 把现有长句阶段名收进「技术详情」。

**R2.2（P0）组件卡内嵌错误块，带三个动作。**
- 页面/位置：出错的组件卡，进度条位置替换为错误块。
- 标题：**「安装没有完成」**；正文一句人话原因，例如「下载中断，已经自动重试 2 次」/「设备空间不足，至少还需要 300 MB」/「下载文件校验失败，已删除损坏文件」。
- 按钮按原因出现：**「重试」**、**「换一个下载源」**、**「清理下载缓存」**、**「查看存储占用」**、**「复制错误信息」**。
- 技术异常原文放在「详情」折叠里，默认不显示。
- 验收：失败后不用滚动、不用切页，一次点击就能重试或换源。

**R2.3（P0）全局错误出口。**
- 页面/位置：主壳 `Scaffold` 顶部，`OperationBanner` 下方，所有 Tab 都显示。
- 当 `snapshot.error` 从空变为非空，显示一条可关闭的错误条：**「安装失败：<一句原因>」** + **「处理」** + **「×」**。
- 「处理」打开当前操作的详情卡，直达 R2.2 的动作；关闭后错误仍保留在工作台，不丢。
- 同一错误只提示一次，避免每个重组都弹。

**R2.4（P1）开始前给真实预期。**
- 页面/位置：一键准备确认弹窗、Ubuntu/Node 组件卡底部。
- 文案：**「Ubuntu 约 29 MB，Node.js 约 58 MB；基础工具和 DSH 依赖另计。至少预留 1.5 GB，建议 4 GB。网络快时通常十几分钟。」**
- 不写虚假总下载量；DSH 阶段明确写「依赖大小以官方源为准，无法提前精确估算」。

**R2.5（P1）说明等待期间可以做什么。**
- 页面/位置：所有安装进度卡下方。
- 文案：**「可以切到其他应用或锁屏，安装会继续；通知栏可看进度。不要强行停止 Tanuki。」**
- 如果系统可能限制后台，补一句 **「部分手机会限制后台，回到应用即可继续查看」**，不要承诺绝对不会被杀。

**R2.6（P2）统一取消文案与恢复入口。**
- 所有位置统一为 **「取消安装」**。
- 取消后组件卡显示 **「安装已取消，已下载的部分会保留」** + **「继续安装」**；只有确实会丢弃缓存时才写「已清理」。

**R2.7（P1）通知权限先解释再申请。**
- 页面/位置：第一次点安装前，应用内小卡。
- 文案：**「允许通知后，锁屏也能看到安装进度和失败提醒；不允许也不影响安装。」**
- 按钮：**「允许通知」** / **「暂不」**。只有点「允许通知」才触发系统权限弹窗。

**R2.8（P1）60 秒无进展的提示前置。**
- 页面/位置：组件卡进度条下方，不必打开弹窗。
- 文案：**「已经 1 分钟没有新进展，可能仍在解压或等待网络。可以继续等，或打开进度详情取消。」**
- 同时保留「查看进度」按钮。

**R2.9（P2）换源要说明原因。**
- 页面/位置：下载进度卡的来源行。
- 文案：**「A 源返回 403，已切换到 B 源继续下载」**；换源后保留一行「已尝试：A（失败）、B（当前）」。
- 如果全部源失败，错误块写 **「所有下载源都失败，请检查网络后重试」**。

**R2.10（P1）WebView 失败给替代路径。**
- 页面/位置：WebView 升级卡。
- 文案：**「当前网页内核不支持 DSH 界面。你仍然可以使用文件、浏览器和运行环境；升级内核后再回来打开 DSH。」**
- 按钮：**「去升级」** / **「稍后」**；「稍后」后 DSH 页显示「内核不满足，暂时无法打开 DSH」而不是空白。

## 3. 聊天：新建、发送、流式、停止、重试、审批、工具、切会话

### 3.1 现状步骤

**A. 官方界面（默认）**
1. 点底部「DSH」。
2. 若服务未运行，点「启动 DSH」；若环境未装，按钮是「下载并准备环境」。
3. 在官方网页里新建会话、输入、发送。
应用外壳只提供 Tab、顶部栏和 WebView；会话创建/发送按钮由官方页面渲染。

**B. 原生界面**
1. 点右上角齿轮 →「网页与兼容性」。
2. 打开「界面：官方界面 / 原生界面」开关。
3. 回「DSH」Tab。
4. 发消息：输入框 +「↑」；空闲提示是「Ctrl/⌘+Enter 发送」。
5. 停止：输入框右侧「■」，或消息列表下方「停止生成」。
6. 失败：消息流底部的「发送失败」卡，按钮「重试 / 填入输入框 / 复制内容」。
7. 审批：消息列表上方「审批请求」窄条 → 底部抽屉 → 逐条「允许/拒绝」。
8. 工具输出：工具卡默认折叠；失败默认展开；按钮「复制输出」。
9. 切会话：顶部横向会话条，点一下切换。

**C. 原生界面新建会话（当前唯一路径）**
1. 齿轮 →「网页与兼容性」→「原生会话管理」。
2. 点右下角「新建会话」。
3. 标题可留空 →「创建」。
4. 返回 DSH 页，再在横向会话条里找到它。

### 3.2 摩擦点

**F3.1 官方界面没有应用级「新建会话」入口。**
用户点进 DSH 后看到的是一整页网页。应用顶部栏只有返回、浏览器小窗、全屏、刷新、设置，没有「新建会话」。第一次用的用户不知道要在网页里找哪个按钮。

**F3.2 原生页明确告诉用户「这里不能新建」。**
空态原文：「官方 DSH 尚无会话。在官方界面创建任务后，这里会显示官方会话。原生页不另建会话库。」用户会理解成「这个界面是只读的」，从而退出原生模式。

**F3.3 原生页不能看全部会话，也没有搜索。**
只有一条横向滚动的会话条；会话多了以后，找某个历史会话只能左右滑。全部会话/搜索/归档都在另一个 Activity，入口在设置第 3 层。

**F3.4 原生/官方切换入口在设置深处，标签也不像开关。**
设置行标题是「界面：官方界面 / 原生界面」，读起来像说明而不是开关。用户想从官方切到原生，必须离开聊天页去设置。

**F3.5 两个「停止」语义不同。**
工作台标题旁的「停止」会停止整个 DSH 服务（内容描述是「停止 DSH 服务」，但可见文字只有「停止」）；聊天里的「停止生成」只停当前回合。用户在任务运行时点错，会中断整个服务，虽然确认弹窗有解释，但入口本身没有区分。

**F3.6 触屏用户看到「Ctrl/⌘+Enter 发送」。**
输入栏空闲状态写「Ctrl/⌘+Enter 发送」，这是硬件键盘提示。手机用户没有这个键，第一次会不知道怎么发；虽然右侧有「↑」，但没有任何文字说明它是发送。

**F3.7 审批没有全局提示。**
审批入口只在原生聊天页的消息列表上方。用户在文件页或设置页时，即使有审批待处理，应用内也没有全局角标/横幅；只有开了系统通知才可能收到提醒。用户会以为 AI 卡住了。

**F3.8 发送失败卡可能滚出视野。**
失败卡插在消息流末尾；如果用户上滑看历史，失败卡不在视口内，也没有顶部「发送失败」角标。用户会以为消息发出去了。

**F3.9 「归档」和「删除」的语义反直觉。**
会话详情里「归档会话」实际是从列表移除且不提供撤销；下面又有一个不可点的「删除会话」说明行，看起来像坏掉的按钮。用户会反复点「删除会话」。

**F3.10 流式失败/断线后的「任务是否还在跑」不清楚。**
原生页有「实时连接提示」和「重新连接」，但没有告诉用户「当前回合可能仍在服务端运行，重新连接后会继续显示」还是「已经中断」。用户会重复发送。

### 3.3 建议改法

**R3.1（P0）在 DSH 页顶部加统一的「＋ 新建会话」。**
- 页面/位置：DSH 页顶部栏，刷新图标左侧；官方与原生都显示。
- 图标按钮：**「＋」**，内容描述 **「新建会话」**；长按提示「新建后直接进入输入框」。
- 原生模式：直接调用现有 `createSession`，创建后选中并聚焦输入框。
- 官方模式：优先调用同一官方 `session/create`，然后切到该会话；如果协议暂不支持，则打开「原生会话管理」并自动弹出新建对话框，创建后返回 DSH。

## 4. 文件：导入、打开、复制/移动、删除、重命名

### 4.1 现状步骤

| 任务 | 当前路径 | 应用内点击 |
|---|---|---|
| 从手机导入 | 文件 Tab → 右上角「⋮」→「导入文件到工作区」→ 系统选择器 | 3 次 + 选择器 |
| 浏览手机文件 | 文件 Tab → 顶部位置下拉 →「手机存储」→（首次）「授权访问手机文件」→ 系统设置 → 返回 → 逐级进入 | 3 次 + 系统授权 |
| 打开文档 | 进入文件夹 → 点文件 → 查看器 | 1 次/文件 |
| 从手机复制到工作区 | **没有直接路径**；只能打开文件 → 查看器「复制到工作区」，或走「导入文件到工作区」 | 无固定路径 |
| 移动 | 仅工作区内可用；手机存储的条目菜单没有复制/移动/删除/重命名 | — |
| 删除 | 长按条目进入选择 →「删除」→ 确认 | 3 次 |
| 重命名 | 条目右侧「⋮」→「重命名」→ 输入 →「保存」 | 3 次 |

### 4.2 摩擦点

**F4.1 导入后出现一个随机名文件夹，而且列表不刷新。**
`WorkspaceStorage.importFiles` 把内容放到 `workspaces/import-<uuid>`。用户导入「合同.pdf」，回到文件页看到的可能是「import-3f2a9c...」；而且 `WorkspaceFilesPage` 的 `entries` 只在位置/权限变化时重新加载，导入完成不会自动刷新，也不会跳到新项目。用户会以为导入失败，或者不知道文件去哪了。

**F4.2 导入入口藏在右上角「⋮」里。**
文件页顶部一行已经有搜索、刷新、排序、更多四个图标，再加权限 chip；没有主「导入」按钮。空态文案说「从右上角菜单新建文件夹、文本文件或导入项目」，但菜单项实际叫「导入文件到工作区」，措辞也不一致。

**F4.3 手机存储不能复制/移动到工作区。**
`DirectoryPicker` 只列当前 `location` 下的文件夹，`files.copy` 也只作用于当前 `WorkspaceFileManager.inLocation(location)`。用户在「手机存储」里选「复制」，目标选择器仍然只显示手机目录，无法选「工作区」。文件夹更没有办法。

**F4.4 「授权本次 DSH 写入」不等于文件页可写。**
权限 sheet 里写「允许本次 DSH 运行期间新建、修改、重命名和删除系统已授权的手机共享文件」，但 `FileLocation.PHONE.writable` 永远是 `false`，文件页的复制/移动/删除/重命名按钮永远不会对手机存储出现。用户会以为授权失败，或者以为按钮坏了。

**F4.5 长按选择没有提示。**
批量复制/移动/删除依赖长按；界面上没有「选择」按钮或「长按可多选」的提示。普通用户很难发现。

**F4.6 复制/移动的同名冲突只在结束后用一句技术话说明。**
结束后文案是「已完成 X 项；未处理：A、B。检查是否同名、链接或空间不足；已有文件未覆盖。」用户不知道到底跳过了几个、为什么跳过、怎么处理。

**F4.7 外部文件「复制到工作区」没有完成反馈。**
查看器里点「复制到工作区」后，只开始一个传输任务；完成后查看器没有提示，也不会跳到新项目。用户会重复点。

**F4.8 「导入」实际是「新建项目」，语义不一致。**
菜单叫「导入文件到工作区」，设置页叫「导入文件」，但底层是 `WorkspaceStorage.importFiles`，会新建一个 `import-*` 项目目录。用户以为是把文件复制到当前文件夹，结果多了一个项目。

**F4.9 权限 chip 只写「只读/可写」，不写作用于哪里。**
文件页右上角的 chip 只显示「只读」，sheet 里才说明是「DSH 运行中，修改已暂停」。用户会以为整个应用只读，或者以为手机存储也受同一个开关控制。

**F4.10 位置名称偏技术。**
「工作区 / 用户目录 / Ubuntu 文件 / 手机存储」四个位置，没有一句「项目应该放哪」。普通用户不知道「用户目录」和「Ubuntu 文件」有什么区别，也不知道哪些位置能改、哪些只能看。

**F4.11 三种「导出」分散在不同地方。**
文件页「导出整个工作区」、查看器「导出此文件」、设置「导出项目 ZIP」；文案没有说明包含/不包含什么。用户容易导出错范围。

**F4.12 DSH 运行时修改按钮变灰，没有就地解释。**
条目菜单里的重命名/复制/移动/删除在 DSH 运行时被禁用，但点灰按钮没有反应；只有权限 sheet 里才解释「DSH 运行中，修改已暂停」。

**F4.13 大文本文件没有「为什么不能编辑」。**
查看器的「编辑」只在文本 ≤256 KiB 时出现；超过时直接没有按钮，用户不知道为什么。

## 5. 远程连接：从零到连上（含配对）

### 5.1 现状步骤

1. 齿轮 →「远程主机」。
2. 点「新增远程连接」。
3. 第 1/6 步「选择连接方式」：直连 SSH / 配对链接 / 局域网；点一张卡 →「下一步：填写主机与账号」。
4. 第 2/6 步「填写主机与账号」：主机、SSH 端口、用户名、远程 DSH 端口、可选 token；配对模式改为配对链接 + 6 位码；→「下一步：选择认证」。
5. 第 3/6 步「选择认证方式」：密码 / 私钥；选私钥文件或粘贴；→「下一步：核对指纹」。
6. 第 4/6 步「核对主机指纹」：勾选「我已通过独立渠道核对」→「核对无误，继续测试」。
7. 第 5/6 步「测试连接」：TCP → SSH 握手 → 认证 → 端口转发 → DSH 探测；失败停在实际阶段。
8. 第 6/6 步「完成」：填连接名称 →「保存并连接」。

进入 3 次点击 + 向导内约 6 次点击 + 4 个字段。前置条件：远程电脑已开机、sshd 可连、远程 DSH 已启动并监听 127.0.0.1；配对模式还需要电脑端运行主机 agent 与 TLS 中继。

### 5.2 摩擦点

**F5.1 没有前置条件检查。**
用户可以直接进向导，填完 6 步才在「测试连接」失败。失败原因可能是「电脑没开」「没装 DSH」「sshd 没开」，这些本可以在开始前用 3 个问题排除。

**F5.2 配对模式要求用户自己在电脑上跑脚本，应用里没有路径。**
界面只说「配对链接由远程主机端生成」。普通用户不知道主机端是什么、去哪下载、怎么启动中继、怎么拿到 6 位码。这个模式实际上只对能读文档、能跑 Python 的用户可用。

**F5.3 指纹核对要求用户在电脑上执行命令，但没有复制按钮。**
文案写「请在远程主机执行 ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub（ECDSA 用对应文件）并逐字核对」。手机用户要手动抄命令到电脑，容易抄错；也不知道输出里的哪一段是要对比的 SHA256。

**F5.4 关闭向导会丢失全部草稿。**
`wizard = null` 直接丢弃 `WizardSession`；用户接个电话回来，6 步白填。没有「保存草稿」或「放弃填写？」确认。

**F5.5 默认认证方式是私钥。**
`RemoteHostDraft.auth` 默认 `PRIVATE_KEY`。很多用户平时用密码登录，第一步就被「选择私钥文件」吓到；界面没有「不确定选哪个」的解释。

**F5.6 连接成功后不跳转。**
「保存并连接」成功后仍停在设置页，只在状态卡显示「已连接」。用户不知道下一步要去 DSH 页；没有「打开远程 DSH」按钮。

**F5.7 远程断开可能静默。**
连接断开后自动回退本地；如果本地 DSH 正在运行，DSH 页直接显示本地网页，没有全局提示「远程已断开，已切回本地」。用户会以为远程任务消失了。

**F5.8 高级字段没有折叠。**
远程 DSH 端口、DSH token 与主机/账号放在同一屏。普通用户不知道 3080 是什么，也不知道 token 要不要填；虽然都有说明，但信息量偏大。

**F5.9 Ed25519 不支持，但提示只在选私钥后出现。**
现代 SSH 用户常用 Ed25519；选完私钥才看到「当前支持 RSA/ECDSA，Ed25519 暂不支持」。用户已经填了 2 步，才发现要换密钥。

**F5.10 配对链接只能粘贴，不能扫码。**
长链接 + 6 位码，手动输入容易出错；当前没有相机扫码入口。

### 5.3 建议改法

**R5.1（P1）向导前加「开始前确认」。**
- 页面/位置：「远程主机」页，「新增远程连接」上方。
- 三行勾选：
  1. **「电脑已开机，和手机在同一网络或可被访问」**
  2. **「电脑已安装并启动 DSH」**
  3. **「我知道电脑的 SSH 地址、用户名，以及密码或私钥」**
- 主按钮 **「都满足，开始连接」**，未全勾选时禁用；文字按钮 **「不确定？查看准备步骤」** 打开说明。

## 6. 更新与版本管理

### 6.1 现状步骤

| 任务 | 当前路径 | 点击 |
|---|---|---|
| 检查应用更新 | 齿轮 →「引擎与更新」→「应用更新」→「检查更新」 | 4 |
| 安装应用更新 | 上一步 →「下载更新」→「安装更新」→ 系统安装器确认 | 7 |
| 卸载旧版本 | 应用内没有入口；只能去系统设置卸载 | — |
| 回退应用版本 | 应用内没有入口；更新策略要求 versionCode 必须更高 | — |
| 切换 DSH 版本 | 工作台 → 展开 DSH →「已安装版本」→「切换」→ 确认 | 5 |
| 卸载备用 DSH | 同上 →「卸载」→ 确认 | 5 |

### 6.2 摩擦点

**F6.1 更新入口不在用户会找的地方。**
「应用更新」在「设置 → 引擎与更新 → 应用更新」，不在「关于与诊断」。大多数用户会在「关于」里找版本和更新；现在「关于」只有版本号、许可和清除缓存。

**F6.2 「不要卸载旧应用」只是卡片底部的一行小字。**
原文：「覆盖更新保留已安装的 Ubuntu、Node.js、DSH 和项目。不要卸载旧应用，也不要清除数据；正式签名与开发签名不能相互覆盖。」这行字在下载按钮下方、技术说明之后，视觉权重很低。用户如果按常规习惯「先卸载旧版再装新版」，会丢失全部本地环境、会话和项目，且无法恢复。

**F6.3 更新通知里的路径是错的，点击也不落到更新页。**
通知文案写「可在“设置 → 应用更新”查看」，实际路径是「设置 → 引擎与更新 → 应用更新」。点击通知只打开 MainActivity 默认工作台，不会打开更新卡。

**F6.4 没有回退指引。**
应用更新只允许更高 versionCode；用户想回退时，应用内没有任何说明。Android 也不允许直接降级覆盖安装；用户可能选择卸载再装旧版，正好触发数据丢失。

**F6.5 没有更新内容。**
更新卡只显示版本号、包名、大小；没有更新说明、修复项、是否必须更新。用户无法判断要不要现在装。

**F6.6 应用更新与 DSH 更新分散在两个地方。**
应用更新在「引擎与更新 → 应用更新」；DSH 更新在工作台 DSH 组件卡或「组件维护与诊断」。两个都叫「更新」，用户容易以为检查了一个就检查了全部。

**F6.7 签名不一致的错误太技术。**
错误写「更新签名与当前应用不同，已保留现有环境」。用户不知道什么是签名，也不知道该做什么；下一步只能放弃。

**F6.8 DSH 版本管理的入口太深。**
「已安装版本」在 DSH 组件折叠卡里；从设置进入要 3 层再展开。用户想卸载旧 DSH 版本时找不到。

**F6.9 「卸载旧版本」这个概念在应用内不存在。**
用户的任务清单里有「卸载旧版本」，但应用只支持覆盖安装。没有一句话解释「Android 应用更新不需要卸载；卸载会丢数据」。

### 6.3 建议改法

**R6.1（P0）把「不要卸载」升级为安装前的显式警告。**
- 页面/位置：应用更新卡「安装更新」按钮上方，红色/警告色块。
- 标题：**「更新时不要卸载旧版本」**
- 正文：**「直接覆盖安装即可。卸载 Tanuki 会删除 Ubuntu、DSH、会话和全部项目，且无法恢复。」**
- 首次更新时，在启动系统安装器前加一个应用内确认弹窗：**「我已知晓，继续安装」** / **「取消」**；勾选「以后不再提示」可选，但警告块始终保留。
- 验收：用户在看到系统安装器前，必定看到过一次「卸载会丢数据」。

**R6.2（P0）修通知路径并做深链。**
- 页面/位置：`UpdateNotifier` 文案与 PendingIntent。
- 文案改为 **「可在“设置 → 引擎与更新 → 应用更新”查看」**；DSH 通知改为 **「可在“设置 → 引擎与更新 → 组件维护与诊断”查看」**。
- PendingIntent 增加 extra（例如 `open_settings_section=应用更新`）；MainActivity 收到后切到设置 Tab 并打开对应 section。
- 验收：点通知直接看到「检查更新/下载更新」按钮，不需要再找路径。

**R6.3（P0）在「关于与诊断」顶部加「检查更新」。**
- 页面/位置：设置 → 关于与诊断，第一行。
- 行标题 **「应用更新」**，右侧显示当前版本 + 状态 pill（「有新版本」/「已是最新」/「上次检查失败」）。
- 点击进入现有「应用更新」卡；如果已有新版本，直接显示「下载更新」。
- 设置齿轮上加一个小红点，直到用户看过更新页。

**R6.4（P1）加「版本与回退」说明。**
- 页面/位置：应用更新卡底部「版本与回退」折叠。
- 文案：**「Android 不允许直接安装更低版本。需要回退时：先导出项目 ZIP、创建私有快照，再按发布说明在电脑上安装旧版；不要卸载应用。」**
- 按钮：**「导出项目 ZIP」** / **「创建私有快照」**，直接调用现有能力。
- 说明「私有快照只保存在应用内，卸载即丢失」，不要给用户「卸载后还能恢复」的错觉。

**R6.5（P2）加更新说明与版本号。**
- 页面/位置：可用版本区域。
- 显示 **「当前 <版本>（code <n>）→ 新 <版本>（code <m>）」**；如果有发布说明，折叠显示「更新内容」。
- 没有说明时明确写 **「本次更新未提供说明」**，不要留空。

**R6.6（P1）做一个统一「更新」页。**
- 页面/位置：设置 → 引擎与更新 → 更新中心。
- 三行：**「Tanuki 应用」**、**「DSH 引擎」**、**「WebView 内核」**，各自显示当前版本、最新版本、状态和动作。
- 这样用户不用分别去工作台、组件维护、网页与兼容性三处检查。
- 原有入口保留为深链，不重复实现逻辑。

**R6.7（P2）签名错误给人话下一步。**
- 页面/位置：应用更新失败卡。
- 文案：**「这个安装包与当前应用签名不同，不能覆盖安装。请从本项目官方发布页下载与当前安装一致签名的版本；不要卸载当前应用。」**
- 按钮 **「打开官方发布页」** / **「复制错误信息」**。

**R6.8（P2）DSH 版本管理加直达入口。**
- 页面/位置：设置 → 引擎与更新，新增一行 **「DSH 版本管理」**，副文案「切换、卸载备用版本；当前使用版本不可卸载」。
- 点击直接打开现有 `DshVersionManagerDialog`，不必先进工作台展开组件卡。

## 8. 出错时：断网、磁盘满、权限被拒、DSH 崩溃

### 8.1 现状对照

| 场景 | 界面现在说什么 | 用户会怎么想 | 下一步是否可执行 |
|---|---|---|---|
| 安装时断网 | 底部「需要留意」→「下载中断（已重试 2 次）：……请检查网络或切换下载源」 | 「它是不是还在重试？」「切换下载源在哪里？」 | 只能自己找回组件卡再点安装 |
| DSH 版本检查断网 | 阶段「官方版本获取失败，可重试」 | 「重试按钮呢？」 | 再点「获取官方版本」 |
| 应用更新断网 | 更新卡「网络或校验超时，可重试；现有应用与环境未改动」 | 清楚 | 「检查更新」可重试 |
| 聊天断网 | 原生页「网络连接中断」+「检查 DSH 服务状态后重试」+「重试」 | 不清楚是手机断网还是本地服务断了 | 有「重试」 |
| 磁盘满（安装前） | 底部错误「至少需要 1.5GB 可用空间，建议预留 4GB」 | 「怎么清理？清理什么？」 | 无按钮 |
| 磁盘满（下载中） | 「空间不足，下载已停止；项目不会被删除」 | 「那现在删什么？」 | 无按钮 |
| 磁盘满（导入） | Snackbar「设备剩余空间不足，已保留原有项目」 | 提示一闪而过，没看清 | 无 |
| 手机存储权限被拒 | 文件页空态「浏览手机文件」+「授权访问手机文件」+ 说明可改用系统选择器 | 清楚，但不知道系统设置里选哪项 | 有按钮 |
| 文件访问授权失效 | 查看器「操作失败，请检查文件是否仍存在、空间是否充足，然后重试。」 | 不知道是权限失效 | 只有「重新选择文件」/「复制到工作区」 |
| DSH 崩溃（工作台） | 「最近一次启动失败」/「失败类型：…」+ 安全模式说明 +「尝试恢复正常模式（进入 2 分钟试用）」 | 信息全，但技术 | 有恢复按钮 |
| DSH 崩溃（DSH 页） | 「工作空间尚未启动」+「启动 DSH」+ 一行「最近失败」+ 可展开「查看失败信息」 | 「为什么起不来？」「是不是我点启动不够多次？」 | 有错误详情，但没有「安全模式/恢复」动作 |
| 远程断开 | 设置页状态卡更新；本地 DSH 页直接显示本地网页 | 「我的远程任务呢？」 | 需回设置重连 |

### 8.2 摩擦点

**F8.1 错误没有统一出口。**
`OperationCard` 只出现在工作台和 DSH 空态；文件、浏览器、设置页看不到运行错误。`OperationBanner` 在失败后立即消失。用户切页就失去全部上下文。

**F8.2 错误只有「是什么」，没有「点哪里」。**
大多数错误是一段可复制文本，没有「重试 / 换源 / 清理 / 去授权 / 重连」按钮。用户要自己把错误翻译成动作。

**F8.3 错误文案技术化。**
「下载内容长度与声明不一致」「SHA-256 校验失败」「更新签名与当前应用不同」「审批通道异常」——普通用户无法据此行动。需要一句人话 + 一条下一步，技术原文折叠。

**F8.4 权限被拒没有分类。**
手机存储权限、SAF URI 失效、DSH 运行期写入暂停、系统通知权限、安装未知应用、悬浮窗，全部可能显示成「操作失败」或「请检查权限」。用户不知道该去哪个系统页面。

**F8.5 DSH 崩溃恢复入口不在当前页。**
工作台有完整的恢复卡；DSH 页只有「启动 DSH」、失败类型和可展开错误详情。用户在聊天中崩溃，最自然的动作是留在 DSH 页重试，但那里没有「安全模式」「恢复正常模式」等恢复动作。

**F8.6 远程断开可能静默。**
本地 DSH 正在运行时，远程断开后 WebView 回退本地，用户看到的仍是「正常网页」，不知道远程已经掉了。远程任务可能还在跑，用户会以为结果丢了。

**F8.7 错误没有时间/次数。**
同一错误反复出现时，用户不知道是新的还是旧的；没有「上次失败 10:32」「已重试 3 次」。清理后错误不会自动消失，造成「一直报错」的错觉。

**F8.8 没有离线预检。**
下载前不检查网络，直接开始再失败；用户白等重试。应用更新有背景检查，但安装环境没有统一的网络状态检查。

**F8.9 「需要留意」太模糊。**
工作台错误卡标题是「需要留意」，不是「安装失败」或「文件写入失败」。用户不知道严重性。

**F8.10 错误详情可选中，但没有显式「复制」。**
`SelectableCopy` 可以长按选择，但普通用户不知道；没有「复制错误信息」按钮，反馈问题很麻烦。

### 8.3 建议改法

**R8.1（P0）统一错误组件与全局出口。**
- 页面/位置：主壳顶部全局错误条 + 各页面内嵌错误卡。
- 结构固定：**图标 + 一句人话标题 + 一句原因 + 1–3 个动作 + 「详情」折叠 + 「复制错误信息」**。
- 标题按场景：**「安装没有完成」**、**「文件没有复制成功」**、**「更新没有完成」**、**「连接断开了」**。不要用「需要留意」。
- 全局错误条保留到用户处理或手动关闭；不要因为切页消失。

**R8.2（P1）断网先检测再开始。**
- 页面/位置：安装/更新/远程测试开始前。
- 无网络时直接显示 **「当前没有网络。连接 Wi-Fi 或移动数据后再试。」** + **「打开网络设置」** + **「重试」**。
- 下载中断网：**「网络中断，已保留下载进度；恢复网络后点重试可续传。」** + **「重试」**。
- 不要显示英文异常或 HTTP 码作为主文案。

**R8.3（P1）磁盘满给清理动作。**
- 页面/位置：错误卡。
- 文案：**「空间不足：还需要约 300 MB，当前剩余 120 MB。」**
- 按钮：**「清理下载缓存」**（直接执行现有 `CACHE`）、**「查看存储占用」**（跳设置 → 存储）、**「重试」**。
- 清理后重新检查空间，不要只提示「已清理」就结束。

**R8.4（P1）权限错误按类型给入口。**
- 手机存储未授权：**「没有手机存储权限」** + **「去授权」**。
- SAF 文件授权失效：**「这个文件的访问授权已失效」** + **「重新选择文件」**。
- DSH 运行期写入暂停：**「DSH 正在运行，文件修改已暂停」** + **「停止 DSH」** / **「知道了」**。
- 通知权限被拒：**「通知权限未开启，后台进度和提醒看不到」** + **「去开启」**。
- 安装未知应用被拒：**「需要允许 Tanuki 安装更新」** + **「去设置」**。
- 每类错误不要共用一句「请检查权限」。

**R8.5（P0）DSH 崩溃恢复卡搬到 DSH 页。**
- 页面/位置：DSH 页「工作空间尚未启动」卡下方，复用工作台的 `RuntimeRecoveryCard`。
- 显示：失败类型、最近失败时间、「已停止自动重启」/「已进入安全模式」。
- 按钮：**「查看原因」**、**「尝试恢复正常模式（2 分钟试用）」**、**「用安全模式启动」**（按当前模式显示）。
- 文案：**「已中断的任务不会自动重放；项目和会话都还在。」**

**R8.6（P1）远程断开全局提示。**
- 同 R5.7；在 DSH 页顶部也显示一条 **「远程已断开，当前显示本地 DSH」** + **「重连远程」**。
- 不要只改设置页状态卡。

**R8.7（P2）错误加时间与重试次数。**
- 页面/位置：错误卡标题右侧。
- 显示 **「10:32 · 已重试 2 次」**；成功恢复后自动清除。
- 同一错误重复出现时合并计数，不要堆叠多张卡。

**R8.8（P2）显式复制按钮。**
- 页面/位置：所有错误卡。
- 按钮 **「复制错误信息」**，复制内容包含时间、阶段、错误原文、应用版本；复制后显示「已复制」。
- 不要只依赖长按选择。
