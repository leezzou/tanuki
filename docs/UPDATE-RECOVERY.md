# 更新和恢复

DSH 程序放在 engines/<version>，用户配置、会话与插件放在 userdata，项目放在 workspaces。APK 更新只替换外壳与原生组件，读取现有安装元数据，不使用 APK 中的默认 DSH 版本覆盖已升级版本。

版本检查使用官方 npm registry 的 @deepseek-ai/dsh 元数据，区分未检查、检查失败、没有更新与有候选版本。候选版本显示来源、完整性、Node 要求（未声明时如实显示）、预发布状态与本机启动检查标记。这个标记只代表本设备的 CLI/Web 启动检查，不能代替模型任务、插件与数据迁移的全面兼容性结论。

安装必须由用户选择版本并确认；先停止服务，不能覆盖运行中的目录。环境修改使用同一个 Mutex。候选 npm 安装使用独立 HOME、DSH_HOME、工作区和引擎目录；固定初始版本的入口 integrity 写在代码中，更新版使用用户刚选择的官方元数据。npm lockfile 与入口 integrity 比对后再提交目录，保留 lockfile 的 SHA-256。候选安装不会修改当前版本的 node_modules。

候选启动检查使用独立配置与空白工作区，监听 127.0.0.1 的系统分配端口，等待官方就绪 URL，并测试官方认证入口。它没有正式账号凭据，也不主动调用模型。旧 Node 与 Ubuntu 环境保持原样，不为了候选测试执行全局 apt/npm 更新。PRoot 不是恶意代码沙箱，因此上述独立目录是避免正常程序误修改正式数据的机制，不是对恶意依赖脚本的强制隔离保证。

通过后，创建包含 userdata 与旧 installed.json 的应用私有快照，再原子切换当前版本元数据、重启正式服务、验证本机 HTTP。正式服务保留其官方设置；例如用户已启用的自动化调度由 DSH 管理。外壳不会为了检查更新主动发起付费模型任务。

快照含凭据，不直接作为明文文件分享到公共目录。它覆盖官方配置、会话、插件、Skills 与匹配版本元数据，不包括工作区代码、Ubuntu 文件系统或 Node 二进制。必要的指向已知客体映射的链接作为链接保存，不遍历复制其目标。恢复时检查匹配 DSH 仍在、Node 版本相同；不能仅凭旧程序目录存在就假定可降级。

恢复需用户明确确认：会话和配置恢复到快照时间，项目代码不回滚。被替换的数据保存在 userdata.before-restore，避免立即丢失新会话。若存在未处理的前次恢复，停止并报告；此版本不自动合并数据库，也不对未知数据格式执行盲目降级。程序启动后的健康状态仍需检查，恢复会话不等于恢复所有旧进程。

事务 journal 保存在 state 中：安装、更新与恢复的中间状态不会被当成成功。候选暂存中断可以重试；正式版本已切换但事务未完成时，可明确选择“检查并保留当前版本”，通过启动检查后保留现有数据，或明确恢复匹配快照。更新、恢复与固定后台自检均纳入前台服务，通知停止会取消相关操作。重新打开 App 时先读取真实文件、组件标记与元数据。进程身份不依据持久化 PID 盲信，App 进程死亡时 supervisor/PRoot 负责终止自己的客体；重新进入显示中断，不重放推送、删除或发布操作。

## 失败出口与恢复卡

安装、更新和运行失败统一收敛为同一展示模型：标题、一句话原因、可折叠的技术详情、主行动与次行动。分类在运行状态写入时完成一次，组件卡、应用更新卡、DSH 页恢复卡和顶部错误条读取同一份结果，不再各自拼接文案。标题按场景为“安装没有完成”“更新没有完成”“DSH 没有正常运行”“文件操作没有完成”；原因说明发生了什么、影响什么和下一步，技术原文只放在“详情”里。

失败后不会只闪一条提示：Ubuntu/Node 组件卡与 DSH 组件卡在折叠区外就地显示原因和“重试/换一个下载源/清理下载缓存/查看存储占用”等动作并自动展开；应用更新卡内嵌同样结构的错误块；DSH 崩溃或启动失败时，DSH 页直接显示恢复卡，提供重新启动、清理下载缓存和切换已安装版本，不必返回工作台。

主壳顶部保留一条可点击的全局错误条，任何 Tab 都能看到；点开可查看详情、执行主动作或复制错误信息，关闭只隐藏本次提示，组件卡里的错误仍在。同一失败只保留一个 key，新的失败会重新提示；服务重新运行、安装环境恢复就绪或更新回到可用状态后，顶部条和旧错误自动消失。错误模型与应用更新映射由 JVM 回归覆盖：分类映射、主行动选择、用户文案不含内部术语、恢复后隐藏以及关闭去重。

当前限制（不能作为已完成能力宣传）：

- Ubuntu/Node 可在固定清单内独立选择版本，见 [组件指南](COMPONENTS.md)，不是所有版本组合都已验收。用户在Ubuntu内追加的apt工具留在当前rootfs中，重装Ubuntu不保留这些系统修改；未实现完整系统工具快照重建。
- 当前主要验证 DSH 独立更新事务。候选版本的本机启动成功不证明所有插件或未来数据库迁移都兼容。
- 内部快照不是可卸载后恢复的加密便携备份。项目通过 SAF ZIP 单独导出；完整账号/会话的加密导出仍待实现。
- 恢复中发生进程终止时以 `prepared → switched → verified` journal 记录，恢复 token 匹配时可在 App 初始化安全完成目录切换；保留较新的旧数据目录，启动检查前显示“数据已恢复，待检查”。专项文件事务测试已验证目录交换中断后新 Paths 创建的空目录不会覆盖暂存数据；实际更新中的恢复仍需跨版本测试。
- 旧 DSH 和快照不自动无限复制 Ubuntu，但也不会为腾空间静默删除历史数据。清理旧引擎与快照的可视化管理仍待完成。
- 官方插件管理修改 profile 内的依赖与启用状态，外壳只管理 engines 里的主 DSH 安装，不擅自批量升级插件。

发布 APK 的步骤：完成最终测试与来源/许可审核；在仓库外生成并备份签名密钥；使用 apksigner 签名与 verify；计算 APK SHA-256；准备版本说明、组件来源、对应源码和已知限制；取得用户明确授权后才公开仓库或 GitHub Release。probe 是 debug 证书签名的非 debuggable 测试构建，不能当作正式发布签名。
