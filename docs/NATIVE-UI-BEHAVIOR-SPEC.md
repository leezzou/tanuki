## 3. 优先级与验收约定

| 优先级 | 判定标准 | 交付要求 |
|---|---|---|
| P0 | 缺了就破坏核心对话闭环或安全闸门：发不出去、看不到回复、停不下来、审批答不了、远程连不上且不知道为什么 | 必须与对应实现同 PR 交付回归；逐条手工验收 |
| P1 | 高频管理与阅读能力：表格/代码/图片、消息操作、工具与轮次、会话列表/搜索/生命周期、模型与权限、SSH 表单 | 可分批交付；每批带定向回归 |
| P2 | 高级或可选：公式/图表、语音、子代理、交付物、用量、分享、网络详情、批量操作、引导 | 排期另定；不阻塞 L1/L2 |

验收记号：

- `M`：手工验收（模拟器或真机），必须记录 AVD 名/serial、API、字体缩放、深色模式。
- `I`：仪器测试可覆盖的交互（不替代手工的视觉与滚动判断）。
- `J`：JVM 可覆盖的纯状态机/解析逻辑（不能替代设备证据）。

通用前置：同一台设备一次只跑一个构建；安装前核对包名与 instrumentation target；测试数据使用合成会话，不接真实模型/账号（用户暂停项）。

## 4. 状态字典

| 术语 | 含义 | 可见表现 |
|---|---|---|
| 贴底（pinned） | 视口底部与内容末尾距离 ≤ 容差（建议 8dp） | 新内容自动跟随 |
| 跟随暂停（held） | 手指在列表上、惯性滚动中、或用户向上滚动 | 不自动滚动，不打断手势 |
| 草稿帧（draft） | 流式已收到但尚未落盘的助手内容 | 临时气泡，不进入持久消息 |
| 落盘（committed） | 收到正式 `assistant/message`，有稳定 seq | 原位替换草稿 |
| 发送中 | 已调用发送、Host 未回显 | 用户气泡 + “发送中” |
| 排队中 | 本轮运行中，消息进入下一轮队列 | “排队中 · 本轮结束后发送” |
| 插话 | 本轮运行中，消息在下一步边界送达 | “插话 · 下一步生效” |
| 中断发送 | 先停止当前回合再发送 | “正在停止并发送” |
| 待确认 / 待回答 | 该会话有审批 / 提问在等待 | 会话行尾部文字标记 |
| 未读 | 会话在用户离开后有新完成内容 | 静默圆点，不抢待处理标记 |
| 轮次（turn） | 一次 `turn/start` 到 `turn/end` | 可整体折叠为摘要 |

## 5. P0 行为规格

### P0-01 流式增量合并与落盘替换

**场景**：用户发送后，助手回复以文本增量持续到达；期间可能出现重复帧、乱序、断线重连、快照重放。

**期望行为**：

- 严格区分两类序号：`chunk.index` 是**内容块序号**，同一块内可连续收到多个有效 `text-delta`，必须按到达顺序全部追加；**增量帧序号**（每次流式帧的单调序号）才用于重放去重与乱序保护。两者不得混用，不能因为块号相同就丢弃后续文字。
- 增量按“尝试（attempt）+ 内容块序号”归并，按帧序号推进游标：帧序号不大于已处理值的帧整帧丢弃；更大的帧序号接受并推进。帧序号出现缺口时不阻塞后续显示，标记缺口并由重连快照补齐。
- 增量先进入草稿，不写入持久消息列表；收到正式助手消息后，用同一稳定行键原位替换草稿，列表不新增一行、不闪、不改变滚动锚点。
- 同一轮同一步只保留最新一次尝试；旧尝试的迟到增量不得覆盖新尝试。
- 断线重连先取快照（含进行中尝试已收到的增量），再续接；快照与本地已显示内容按“事件序号 + 帧序号”幂等合并，不重复、不丢字。
- 收到结束帧后停止“流式中”状态；若 Host 明确未提交，保留已收到的前缀并标记“已中断”，不伪造完成。
- 正式消息迟到时按事件序号去重；重复的正式消息只保留一条。
- 增量合并必须做帧级节流（建议 30–33ms 一次），长回复不得每个增量都触发整页重组。

**关键状态**：

- `draft(attemptId, turn, step, nextFrameSeq, chunksByBlock[], streaming)`
- `committed(seq)`；`interrupted`；`resyncEpoch`
- 行键：`m<turn>.<step>`（草稿与正式消息共用，保证替换不换元素）

**验收步骤**：

1. `M` 发送一条会产生 2000 字以上回复的消息，观察 30s：文字连续增长，无整段回退、闪烁、重复段落。
2. `M` 流式中切到其他会话再切回：已显示内容不丢，返回后继续增长。
3. `M` 流式中开飞行模式 5s 再恢复：恢复后不重复整段，缺口由后续增量或重连补齐。
4. `J` 同一内容块（`chunk.index=0`）用三个不同帧序号依次注入文本 `"历史"`、`"前缀"`、`"。"`：断言输出为 `"历史前缀。"`，证明同块后续增量全部保留。
5. `J` 重放第 2 帧（帧序号相同）：断言输出仍为 `"历史前缀。"`，整帧只处理一次。
6. `J` 注入帧缺口（f1、f3）后补发快照中的 f2：断言最终文本完整、顺序正确且无重复。
7. `J` 注入“正式消息先到、迟到增量后到”，断言草稿被移除且正文不回退。

**边界**：同块多帧、整帧重放、帧缺口、快照 replace、同一轮多次尝试、长回复中途取消。

### P0-02 流式 Markdown 的稳定呈现

**场景**：回复还在逐字到达，末尾经常停在半个粗体、半张表、半截链接或未闭合代码围栏上。

**期望行为**：

- 只修补“最后一个未完成块”，已完成内容不重算。
- 未闭合的 `**粗体**`、`*斜体*`、`~~删除线~~`、`` `行内代码` `` 按“即将成立”的样式渲染，不显示裸露标记；标记后还没有内容时先不显示该标记。
- 半截链接按链接样式显示已输入的文字；半截图片整体暂缓，不显示破图或 alt 占位闪动。
- 表格只有在分隔行完整后才出现；在此之前不把管道文本当段落显示再跳成表格。
- 孤立的 `#`、列表符号、`---`/`===`、`<tag`、未闭合围栏的起始行暂缓显示，直到能判断块类型。
- 围栏代码内部按原文流式显示；只有开启行的语言信息还在输入时暂缓。
- 光标跟在最后一段文字末尾（呼吸效果），不是固定在屏幕底部；正文停顿 ≥900ms 时改为静态呼吸点，避免“假活跃”。
- 揭示节奏：建议约 120 字/秒；显示落后已到达内容不超过 0.35s；积压时自动加速，最低 24 字/秒；新字 0.24s 淡入。
- 回复完成后不再重排：最终渲染必须与流式最后一帧一致，不得出现“结束后字号/间距跳变”。

**关键状态**：`streaming`、`tailBlockStart`、`openFence`、`revealBuffer`、`stalled`

**验收步骤**：

1. `M` 构造一条包含“粗体 + 表格 + 围栏代码 + 链接 + 图片”的回复，逐字注入观察：无标记裸露、无表格跳变、无破图。
2. `M` 在流式中旋转屏幕、切深色、放大字体到 1.3×：不崩溃、不重叠、光标仍在末段。
3. `J` 对 `**bold`、`[label](https://exa`、`| a | b |\n|---|` 等未完成输入做快照断言（修补结果稳定）。
4. `M` 回复完成后对比最后一帧与完成态：文字位置与样式不跳。

### P0-03 列表跟随与阅读保护

**场景**：长会话中阅读历史时，实时回复仍在增长；或用户刚发送消息，需要立刻看到自己的气泡和回复。

**期望行为**：

- 贴底时，新内容与流式增长在**同一帧**内跟到新底部；不得先被输入条遮住一帧再跳上来。
- 用户手指触到列表、开始惯性滚动或向上滚动时立即暂停跟随；不打断手势、不抢滚动。
- 用户回到底部、或自己发送消息后恢复跟随，并立即贴底。
- 离开底部超过约 160dp 显示“回到底部”浮钮；浮钮出现后保持显示，直到重新贴底才隐藏（避免阈值附近闪烁）。
- 非贴底期间到达新内容时，浮钮附带“新内容”提示（点/计数）；点按后贴底并清除提示。
- 切换会话恢复该会话上次阅读位置；首次进入定位到底部。
- 内容高度变化（轮次折叠/展开、图片加载、字体变化）时保持当前可见锚点行不跳。
- 输入条高度变化（多行、键盘、附件托盘）只改变列表下沿，不改变内容锚点。

**关键状态**：`pinned`、`held`、`followWaiting`、`showJump`、`hasNew`、`splitAnchorKey`

**验收步骤**：

1. `M` 打开 200 条以上会话，上翻 3 屏后等待流式回复：视口不动，浮钮出现并带新内容提示。
2. `M` 点浮钮：200ms 内贴底，提示消失。
3. `M` 在底部发送消息：自己的气泡立即可见，回复增长持续可见。
4. `M` 上翻时展开/收起轮次：当前阅读行不跳动。
5. `M` 键盘弹出/收起、输入 3 行文字：列表锚点不跳。

### P0-04 历史向前分页

**场景**：打开一个很长（数千事件）的会话，需要向上加载更早内容，同时实时流仍在写入。

**期望行为**：

- 列表顶部距顶 ≤800dp 时自动加载上一页；每页建议 50–100 条事件，按事件序号升序合并。
- 加载中在顶部显示不定进度条，不遮挡现有内容、不改变滚动位置。
- 到达最早一页显示“没有更早的消息”，不再重复请求。
- 历史插入顶部时保持当前可见行绝对不动（中心锚定或等价的锚点补偿）。
- 分页按事件序号幂等合并；与实时流并发时，迟到页不能覆盖或回退已收到的终态。
- 加载失败在顶部显示“加载更早失败 · 重试”，保留已加载内容。
- 会话切换/返回保留已加载页与滚动位置。

**关键状态**：`hasMore`、`loadingOlder`、`oldestSeq`、`anchorRowKey`、`loadError`

**验收步骤**：

1. `M` 打开 1000+ 事件会话，连续上滑 10 页：不跳、不重复、不白屏。
2. `M` 在顶部加载时观察实时回复：新增内容仍进入底部，不打断分页。
3. `M` 断网后上滑：出现失败提示与重试；恢复网络后重试成功。
4. `M` 加载到最早：显示结束提示，继续上滑不再发请求。

### P0-05 忙碌时发送：排队、插话、中断

**场景**：上一轮还在生成，用户继续输入并发送。

**期望行为**：

- 空闲时发送立即开始新回合，用户气泡先以“发送中”出现。
- 运行中发送默认进入队列（本轮结束后发送）。
- 长按发送键提供三选：插话（不打断，AI 下一步看到）、停下并发送、排队；每项有一句说明。
- 待发送气泡下方显示准确文案：发送中 / 排队中 · 本轮结束后发送 / 插话 · 下一步生效 / 插话中 / 未发送 / 未送达 · 已保留。
- 已在队列中的消息可：撤回（回到输入框，保留文字与附件，提示“已撤回，可修改后再发”）、改为插话、立即发送。
- 撤回先本地移除，再请求 Host 移除；失败恢复气泡并提示，不静默丢失。
- 发送幂等：同一请求 id 重试不得产生两条用户消息；Host 回显后原位替换“发送中”气泡。
- 发送成功清空输入框与已提交附件；发送失败保留草稿与附件，显示“未送达 · 已保留”，提供“编辑后重发”。
- 附件未上传完成、失败或超出限制时禁止发送，并在按钮/托盘给出原因。

**关键状态**：`SendMode(now|steer|queue|interrupt)`、`InboxSlot(nextStep|nextTurn)`、`requestId`、`inboxId`、`failed`、`resendable`

**验收步骤**：

1. `M` 运行中连发 3 条：顺序正确，文案分别为排队/插话，刷新后仍在。
2. `M` 撤回第 2 条：回到输入框且文字附件完整；再发送成功。
3. `M` 把排队消息改为插话：下一段工具步骤后出现，不打断当前工具。
4. `M` 选择“停下并发送”：当前回复出现停止标记，新消息开始新回合。
5. `M` 飞行模式下发送：显示未送达并保留；恢复后重发不重复。

### P0-06 停止当前回合

**场景**：回复方向错误或耗时过长，用户要立即停止。

**期望行为**：

- 运行中显示停止键；点按后立即进入“停止中”（按钮转圈并禁用），发送取消请求。
- 取消幂等：重复点按不重复发送；以 Host 状态流收敛为准，不本地臆断已停止。
- 停止后保留已生成前缀；若正文末尾已有停止标记，不再追加重复的“已停止”行。
- 8–10s 未收敛时提示“停止请求已发送，仍在等待 Host”，提供“重试取消/返回官方界面”，不得显示为已停止。
- 审批或提问等待时，停止键退居次要，主操作是卡片按钮。
- 运行中禁用会冲突的操作（重新回答、编辑重发、分叉当前轮）。

**关键状态**：`running`、`stopping`、`cancelPending`、`cancelSentAt`

**验收步骤**：

1. `M` 长回复中点停止：按钮 2s 内进入停止中，随后回复停止增长。
2. `M` 连续点按 5 次：只发一次取消。
3. `M` 断网后点停止：出现等待提示与重试，不误报已停止。
4. `M` 审批等待时观察：停止键不抢主按钮。

### P0-07 失败轮次与错误恢复

**场景**：模型鉴权失败、欠费、限流、上下文超限、服务 5xx、网络中断、空回复、引擎过旧、模型不支持。

**期望行为**：

- 失败以“消息流内的失败行”呈现：红点 + 一句中文摘要；不用整页错误 banner 替代。
- 错误码到短句的固定映射（至少覆盖）：鉴权失败→API Key 无效；额度→余额不足；账户额度→账户额度不足；限流→请求过快；上下文超限→上下文过长；服务端/5xx→模型服务暂不可用；超时→响应超时；传输→网络中断；空回复→模型未返回内容；引擎过旧→请升级 DSH；模型不支持→当前模型不可用；推理强度不支持→该模型不支持此推理强度；其他→本轮失败。
- 默认只显示短句；可展开/复制脱敏后的详情（截断长度、去 token/路径）。
- 可重试错误提供“重试”；不可重试错误（模型不支持、引擎过旧）不提供无效重试，改为“切换模型/升级引擎”。
- 欠费文案保持中立，不指责用户、不诱导充值。
- 失败后输入框立即恢复可用，草稿与附件不丢；重试不得重复已成功的用户消息。

**关键状态**：`turn.endReason.kind`、`failure.code`、`retryable`、`retryTargetSeq`

**验收步骤**：

1. `J` 用错误码夹具逐项渲染，断言文案与按钮组合。
2. `M` 断网触发传输错误：失败行出现，恢复后重试成功。
3. `M` 构造不可重试错误：只出现“切换模型/升级”，无重试按钮。
4. `M` 失败后检查输入框：可继续输入，附件仍在。

### P0-08 审批卡与批量待办

**场景**：Agent 请求执行命令、写文件、编辑文件、访问网页、搜索等；同一会话可能连续出现多个审批。

**期望行为**：

- 卡片出现在触发它的工具行下方；无法归属到具体工具时按到达顺序附在消息流末尾，不丢失。
- 卡片结构：警示色图标 + 按工具类型生成的标题（如“允许运行这条命令？”“允许写入文件？”）、一句说明、命令/路径等宽代码井（最高约 148dp 内滚动，可选中复制）、理由（最多 3 行省略）、拒绝（描边）与允许一次（主色）等宽两键（高 44dp）。
- 更宽的“本对话都允许”降级为文字按钮，点按后必须二次确认风险；确认文案说明影响范围与撤销方式。
- 回答中按钮原位转圈并禁用；成功后卡片随 Host 取消事件消失；失败恢复可点并显示短错误。
- “本对话都允许”只影响同一会话的后续审批；自动放行时不再显示卡片，但工具行保持运行态；Host 未确认前卡片不消失；记忆只在本次运行，不写配置、不跨重启。
- 已识别但高风险的工具：只提供拒绝与允许一次，不参与“本对话都允许”；是否高风险由工具类型与风险等级判定，不能因风险高就隐藏单次允许。
- 无法识别的审批（工具名缺失、非法或未知类型）：只能拒绝，允许一次与“本对话都允许”均禁用，并在卡片上说明“无法识别操作类型，只能拒绝”；不得把“无法识别”当成“高风险”放行。
- 多个待审批按到达顺序逐张显示，不静默合并、不随机丢弃。
- 其他会话的待审批：在会话列表行显示“待确认”，当前会话顶部提示“其他会话还有 N 个待审批”；切换会话后按该会话过滤。
- 审批通道断开时卡片保留，显示“审批通道未连接 + 重试”，禁止伪造允许；服务重启/端口变化后旧待审批不跨端点回答。

**关键状态**：`pendingApprovals[eventId]`、`answering`、`automatic`、`autoAnswered`、`remembered(sessionId+tool+risk)`、`channelReady`

**验收步骤**：

1. `M` 分别触发命令、写文件、编辑、网页访问四类审批：标题、代码井、理由、按钮符合预期。
2. `M` 回答瞬间连点：只提交一次，按钮转圈。
3. `M` 勾选“本对话都允许”并确认：后续同类审批不再弹卡，工具行继续运行；不同工具仍弹卡。
4. `M` 断网后回答：显示失败并恢复按钮；不得显示成功。
5. `M` 两个会话各留一个审批：列表行标记正确，切换会话只处理当前会话。
6. `M` 未知工具：只有拒绝可用，允许一次与“本对话都允许”均禁用且有说明；已识别的高风险工具可单次允许，但不能“本对话都允许”。

### P0-09 用户提问卡

**场景**：Agent 通过提问工具向用户确认需求，可能一次多题、单选/多选、需要自填。

**期望行为**：

- 支持 1..N 个问题；多题时标题显示题数（如“3 个问题”），单题显示“1 个问题”。
- 每题由题干、选项列表（单选/多选）、可选“其他/自填”组成；没有选项时默认展开自填。
- 单选选中某项后清空并收起自填，避免两份答案冲突；多选可多选，自填与选项可并存。
- 提交按钮仅当**每题**都有选项或非空自填时可用；提交中按钮转圈并禁用整卡。
- 提供“不回答/拒绝”显式结束 Host 请求，不静默隐藏；拒绝与提交左右成对。
- 选择、自填、展开状态在滚动离屏、切会话再回来时保留（草稿按事件 id 存）。
- 回答成功后卡片消失；失败保留答案并显示错误，可重试。

**关键状态**：`picked[question][option]`、`custom[question]`、`customOpen[question]`、`sending`、`declining`、`complete`

**验收步骤**：

1. `M` 构造 3 题（单选/多选/自填）：只答 2 题时提交禁用；答满后可提交。
2. `M` 单选后切到自填：选项清除；再选选项：自填清除。
3. `M` 填一半后滚出屏幕/切会话再回：答案与展开状态都在。
4. `M` 点拒绝：Host 请求结束，卡片消失，不残留。
5. `M` 断网提交：显示失败，答案不丢。

### P0-10 远程连接首连引导

**场景**：用户第一次把手机连到另一台电脑上的 DSH；可能通过账号中继扫码，也可能通过 SSH 直连。

**期望行为**：

- 入口并列说明两种方式：账号中继（扫码/粘贴配对，无需公网与端口映射）与 SSH 主机（地址+账号+认证，需要可达网络）。每种给一句适用场景，不把一种写成另一种的“高级选项”。
- 扫码页：相机取景框、从相册识别、粘贴链接按钮；剪贴板为空给明确提示；识别失败提示“不是有效的配对码”，可重试，不崩溃。
- 流程状态分开显示：读取配对信息 → 确认电脑 → 等待电脑确认 → 连接中。不要用一个笼统转圈覆盖全部阶段。
- 身份确认页显示：电脑名称、服务端地址、完整主机指纹（每 4 组一行、等宽、可长按复制）、如何在本机核对的命令；主按钮“这是同一台电脑”，次按钮“不是这台，重新扫码”。
- 二次确认：手机显示一次性确认码（8 位分组显示）与倒计时；过期显示“已过期，重新生成”；只有电脑端确认后手机才继续；手机不得替电脑确认。若所用协议没有确认码，则以“配对链接中的主机 id + 指纹核对”作为等价确认，不允许跳过。
- 连接阶段进度卡：连接服务器 → 验证主机指纹 → 启动 DSH → 建立隧道 → 登录；每项 done/running/failed/waiting，当前项可显示细节；失败项下显示一句可行动错误 + 可复制详情 + 重试。
- 错误分类与文案：地址不可达、认证失败、私钥无效、主机指纹不匹配、主机离线、未登录、版本不兼容、协议错误；不可重试错误不自动重试。
- 配对码/令牌只用于本次配对：不写日志、不进通知、不出现在错误文本；输入框按敏感内容处理（禁止截图预览/自动补全）。
- 断线自动重连：网络类错误指数退避（1/2/4/8s，最多 4 次尝试），界面显示“重连中”；超出后停在失败页给“重试”；已建立会话不静默切换到别的主机。
- 已连接后切换主机：会话列表与聊天跟随新主机；切回本地保留本地状态与草稿。

**关键状态**：`PairingStep(scanning|resolving|confirming|claiming|showingCode|done|failed)`、`HostLinkPhase(idle|connecting|connected|reconnecting|failed)`、`HostLinkStep(connect|verifyHostKey|startDsh|tunnel|login)`、`codeExpiresAt`、`retryable`

**验收步骤**：

1. `M` 用无效链接、错误令牌、离线主机、指纹变更各跑一次：分别得到对应错误，不崩溃、不误连。
2. `M` 完整走一次扫码配对：确认页指纹可核对，确认码倒计时正确，过期可重新生成。
3. `M` 连接过程中观察阶段卡：五个阶段按顺序点亮，失败停在该阶段。
4. `M` 连接成功后杀远端进程：进入重连中并自动退避；超出后给重试。
5. `M` 前后台切换 30s 再回：配对/连接状态不丢，不重复弹确认。
6. `M` 检查日志与通知：无配对码、令牌、密码。

## 6. P1 行为规格

### P1-01 Markdown 表格

**场景**：回复包含 GFM 管道表，单元格较长或列数较多。

**期望行为**：

- 表头加粗；分隔行决定列数与对齐；列宽随内容，单列上限约 260dp，超长单元格在列内换行。
- 整表宽度超屏时横向滚动，不压缩到不可读；表头与隔行有可区分的底色。
- 表格紧贴上一段文字时自动补空行再解析，不把管道当普通段落。
- 代码围栏内的管道不解析；嵌套表不支持，按普通文本降级。
- 空单元格、缺列单元格补空，不崩溃；行数很多时仍保持滚动流畅。

**关键状态**：`header[]`、`align[]`、`rows[][]`、`scrollX`

**验收步骤**：

1. `M` 4 列 × 20 行、含 300 字单元格：横滑、换行、表头固定可读。
2. `M` 深色模式与大字体：边框与文字对比可读。
3. `J` 表格紧贴段落、缺列、围栏内管道三类夹具解析正确。

### P1-02 代码块与语言高亮

**场景**：回复包含围栏代码、长行、diff、超长输出。

**期望行为**：

- 标题条显示语言名（未知或空显示“代码”）与复制按钮；复制成功图标原地变对勾约 1.2s，不弹遮挡提示。
- 支持常见语言别名归一（如 `ts`→TypeScript、`py`→Python、`sh`→Bash、`yml`→YAML）；未知语言退化为等宽纯文本。
- 默认横向滚动；提供“折行”切换，长行不强制横向拖动。
- `diff` 语言按增/删/上下文行着色，不当作普通文本。
- 超过 20000 字符的代码不做语法高亮，避免卡顿；仍可复制、可横向滚动。
- 可选行号；行号不参与复制与选择。
- 流式追加时前面已完成的块不重新高亮，只重算最后一块。

**关键状态**：`language`、`wrap`、`copied`、`highlightThreshold`

**验收步骤**：

1. `M` 未知语言、`ts`、`diff` 各一条：标签、着色、复制正确。
2. `M` 300 字符长行：默认横滑，切折行后不裁切。
3. `M` 复制按钮：对勾反馈，剪贴板内容与显示一致（去掉末尾多余换行）。

### P1-03 消息图片

**场景**：回复用 Markdown 引用工作区图片、网页图片或 `data:` 图片。

**期望行为**：

- 支持三类来源：会话工作区路径（相对/绝对）、`http(s)`、`data:image/*`。
- 工作区图片按会话授权读取；远程主机只下载一次并缓存；超过 20MiB 拒绝并显示原因。
- 内联显示最大高度约 480dp，按阅读宽度解码，避免整图常驻内存；小图不放大。
- 加载中显示尺寸稳定的骨架占位，避免列表跳动；失败显示“图片加载失败 + 重试”。
- 点击打开全屏查看器：缩放、拖动、保存/分享、关闭；返回后列表位置不变。
- 非图片 scheme（`javascript:`、`intent:` 等）不加载、不执行；未知来源显示占位说明。

**关键状态**：`sourceKind(workspace|web|data|unsupported)`、`loading|ready|failed`、`bytes`、`viewerOpen`

**验收步骤**：

1. `M` 三种来源各一张：显示、点击查看、返回位置不变。
2. `M` 断网加载网页图：骨架→失败→重试。
3. `M` 20MiB 边界图片：拒绝提示，不 OOM。
4. `J` `imageSourceOf` 对危险 scheme 返回不支持。

### P1-04 链接与文件引用

**场景**：回复中包含网页链接、裸域名、工作区文件路径、带行号的文件链接。

**期望行为**：

- `http/https/mailto` 可在确认后外部打开；其他 scheme（`tel:`、`sms:`、`intent:`、自定义 deep link）不启动应用。
- 裸域名（如 `example.com/docs`）补全 `https://` 后按外链处理；看起来像文件名的（`notes.md`、`main.py`）不误判为网站。
- 工作区相对/绝对路径在应用内打开文件预览，不交给系统浏览器；支持 `#L24` 定位行。
- 链接文字与目标不一致时同时显示 label 与 URL，便于识别钓鱼。
- 未知/远程文件 authority 阻止打开并提示。

**关键状态**：`linkKind(web|mail|file|blocked)`、`confirmed`、`line`

**验收步骤**：

1. `M` 点击网页、裸域名、邮件：分别确认/打开正确。
2. `M` 点击 `src/main.kt#L24`：应用内预览并定位。
3. `M` 点击 `javascript:` / `intent:`：被拒绝且有提示。

### P1-05 消息操作

**场景**：用户想复制、引用、编辑重发、分叉或重新回答。

**期望行为**：

- 用户消息长按：复制、选择文字、编辑后重发；编辑后把原文放回输入框，不直接改写历史。
- 助手本轮最后一条回复下方显示操作行：复制、分享、分叉、重新回答（仅会话最后一条）、更多（选择文字、引用）。
- 复制成功有轻提示；分叉/重答进行中按钮转圈并禁用，防连点。
- “重新回答”语义：以该轮之前的上下文创建分支并重发同一输入，不覆盖原会话；原会话保留可回看。
- 凭据类内容（API Key、令牌、私钥、带密码的地址）在界面遮挡，复制/选择/编辑拿到原文。
- 流式中的消息不显示操作行。

**关键状态**：`menuOpen`、`branching`、`regenerating`、`masked`

**验收步骤**：

1. `M` 复制、选择文字、编辑重发各一次。
2. `M` 分叉：新会话出现且不自动跳转；原会话不变。
3. `M` 重新回答最后一条：旧回复仍在原会话，新回复在新分支。
4. `M` 含密钥的消息：界面遮挡，复制得到原文。

### P1-06 思考过程

**场景**：模型先输出推理内容，再输出正文。

**期望行为**：

- 流式中显示一行“思考中”+ 最多 3 行实时窗口，跟随最新文字上滑，高度固定，列表不因思考变长而跳。
- 正文开始后思考不再占据主视觉；一轮结束后收起为一行预览（全文首行、去掉 `**`）。
- 点该行展开全文（次级字号/颜色、Markdown），再点收起；一轮结束后自动收回手动展开。
- 实时窗口与展开全文共用同一位置，切换不叠加、不闪。
- 思考内容不进入复制“整条回复”的正文（只复制最终答案）。

**关键状态**：`reasoning`、`active`、`expanded`、`streaming`

**验收步骤**：

1. `M` 长思考流：窗口最多 3 行，列表不跳。
2. `M` 展开/收起：内容与高度正确，不重叠。
3. `M` 一轮结束后：自动收回，预览为首行。

### P1-07 工具行与工具分组

**场景**：Agent 连续调用命令、读文件、编辑、搜索、网页访问，可能失败或等待审批。

**期望行为**：

- 单行约 32dp：图标 + 动词（运行/读取/编辑/搜索/写入）+ 对象 + 行尾状态；成功默认安静（无对勾），失败红色 ✕，拒绝/取消有文字。
- 等待审批时行尾显示“待确认”，审批卡内联在该行下方。
- 点开详情：命令/参数、输出（ANSI 颜色）、diff、文件变更、图片缩略、错误；详情区最高约 280dp 内滚动，滚到尽头把滚动交还外层消息列表。
- 连续 ≥3 个工具调用收成一组摘要（如“执行 2 条命令 · 读了 3 个文件”）；运行中或待确认的行始终露在摘要外。
- 长输出默认截断并可“展开全部”；不一次性渲染超大文本。
- 子代理调用可点开对应子会话；未知子会话时仍可展开详情。
- 工具行与文本按事件序号交错；迟到结果按 callId 非回退合并（已成功不被旧“运行中”覆盖）。

**关键状态**：`ToolStatus(streaming|running|awaitingApproval|succeeded|failed|denied|cancelled)`、`callId`、`expanded`、`groupSize`

**验收步骤**：

1. `M` 触发命令/读/编辑各一次：行文案与详情正确。
2. `M` 连续 5 次工具调用：成组摘要；运行中的行外露。
3. `M` 工具失败与拒绝：行尾状态与详情正确。
4. `M` 长输出 1MB：默认截断，展开不 ANR。

### P1-08 轮次折叠与回合脚注

**场景**：一轮包含多次思考、工具调用和中间消息，最终给出答案。

**期望行为**：

- 正常完成的轮次收起为一行摘要：“已完成 · N 次工具调用 · M 条消息”；只有思考时显示“已完成 · N 段思考”。
- 最终回答永远留在折叠外；被停止、出错、运行中的轮不折叠。
- 展开显示过程（思考、工具、中间消息），左侧细线表示归属；再点收起。
- 折叠/展开动画补偿滚动高度，摘要行不跳；贴底观看时本轮结束先按展开态出现一帧再平滑收起，上翻阅读时直接收起不播动画。
- 用户插话把一轮切成多段时，每段各自收尾；最后一段保留最终回答与脚注。
- 回合脚注显示用时、步数等，挂在最后一条回复的操作行右端；没有回复时单独一行。

**关键状态**：`turn.startSeq/endSeq/endReason`、`foldTurns`、`processRows[]`、`settling`

**验收步骤**：

1. `M` 多轮长任务：完成轮折叠，最终答案外露。
2. `M` 展开/收起：摘要行不跳，滚动顺畅。
3. `M` 上翻时一轮结束：不播收起动画，内容不移动。
4. `M` 停止/出错的轮：不折叠，失败位置可见。

### P1-09 草稿与附件限制

**场景**：用户在多会话间切换、重启应用，或选择大量/超大附件。

**期望行为**：

- 每会话独立草稿；文本跨重启保留最近 30 个会话，附件只在本次运行保留。
- 切会话、切官方/原生、返回列表再进入，草稿与光标位置合理恢复。
- 附件上限：每条最多 9 个；图片单张 20MiB；文件单个 200MiB；单条总量 400MiB（可按堆内存调整，但必须显示明确上限）。
- 超限逐项拒绝并保留其余选择；提示具体文件名与原因，不整批丢弃。
- 失败附件保留在托盘，可重试或移除；上传中显示已知字节进度或不定进度，不伪造百分比。
- 发送前所有文件必须就绪；否则发送按钮禁用并说明原因。

**关键状态**：`drafts[sessionId]`、`attachments[]`、`status(reading|ready|uploading|uploaded|failed)`、`bytes`

**验收步骤**：

1. `M` A 会话输入一半切 B 再切回：文字与附件都在。
2. `M` 杀进程重启：最近会话文本恢复，附件不恢复（符合预期）。
3. `M` 选 10 个文件：第 10 个被拒，前 9 个保留。
4. `M` 超大文件与断网上传：失败项保留，可重试。

### P1-10 附件入口与发送呈现

**场景**：从相册、拍照、文件、粘贴、拖入添加附件。

**期望行为**：

- “+”面板提供相册、拍照、文件；能力不足时隐藏对应项，不显示死按钮。
- 支持多选与粘贴图片；平板/桌面模式支持拖入，拖入时有可放置提示。
- 托盘按选择顺序显示缩略图/文件卡、名称与大小、移除按钮、失败标记。
- 发送后附件按原顺序显示在用户气泡上方（不塞进正文），图片可点开查看。
- 附件卡与历史消息附件在重启后仍可查看（历史图片按会话授权读取）。

**关键状态**：`source(gallery|camera|files|paste|drop)`、`order`、`remove`、`sendSnapshot`

**验收步骤**：

1. `M` 三种入口各加一张/一个：顺序与托盘正确。
2. `M` 粘贴截图、拖入文件：进入托盘，可移除。
3. `M` 发送后查看历史：附件卡顺序与内容正确。

### P1-11 会话列表

**场景**：会话数量多，存在置顶、文件夹、运行中、待审批、未读。

**期望行为**：

- 行高约 44dp，标题单行省略；当前会话软底色 + 加粗。
- 每行最多一个尾部标记，优先级：待确认/待回答（文字）> 运行中（呼吸点）> 未读（静默点）。
- 分组顺序：置顶 → 文件夹 → 按天（今天/昨天/本周/更早）；文件夹可折叠，成员缩进约 30dp。
- 状态筛选：全部/运行中/待处理/未读；筛选时扁平显示，不保留分组。
- 长按进入多选：复选、全选、批量归档；顶部显示计数与退出；返回键退出多选。
- 加载、空、错误状态分开；错误给重试；空状态给“新建会话”。
- 大字体/深色下不截断关键状态文字；读屏能读出标题、状态与选中态。

**关键状态**：`sessions[]`、`current`、`pendingKind`、`unread`、`pinned`、`folders`、`filter`、`selection`

**验收步骤**：

1. `M` 造 20 个会话、3 个置顶、2 个文件夹、各状态各 2 个：顺序与标记正确。
2. `M` 切换筛选与多选批量归档：计数、结果、返回行为正确。
3. `M` 字体 1.3×/2.0× 与深色：不截断、不重叠。

### P1-12 会话搜索

**场景**：按标题或消息内容找历史会话。

**期望行为**：

- 全屏搜索；标题匹配即时（本地逐字），内容搜索 250ms 防抖后请求 Host。
- 内容命中最多 20 条，显示命中上下文摘录并高亮关键词；显示日期与所属文件夹。
- Host 不支持内容搜索时明确显示“仅搜索标题”；20s 超时给出提示，不无限转圈。
- 归档会话可单独浏览并“恢复并打开”；恢复失败提示。
- 无结果提示换关键词；清空搜索回到最近会话。
- 选中结果后打开会话并关闭搜索，返回不残留搜索态。

**关键状态**：`query`、`titleMatches`、`contentStatus(idle|pending|done|unsupported|timeout)`、`archivedOnly`

**验收步骤**：

1. `M` 输入标题片段：即时命中；输入内容关键词：250ms 后出摘录。
2. `M` 断开 Host：标题仍可搜，内容搜索显示不可用。
3. `M` 浏览归档并恢复：成功后出现在列表。

### P1-13 会话生命周期

**场景**：新建、重命名、分叉、归档/撤销。

**期望行为**：

- 新建优先当前/最近工作区；存在空白会话时复用并保留草稿；无工作区先选工作区。
- 重命名预填当前标题；空标题回到自动标题；上限 200 字；保存失败保留输入。
- 分叉从最近完成轮次或指定事件位置创建子会话；不自动跳转，提示“已创建分支”。
- 归档：静止会话直接归档，4s 内可撤销；运行中先确认“停止并归档”，列出将停止的工作；撤销窗口内不发请求；提交失败回滚并提示。
- 归档不是删除；界面不得宣称删除项目文件；没有删除端点时不伪造删除。
- 只读/安全模式禁止重命名/归档，并说明原因。

**关键状态**：`pendingArchive(ids, timer)`、`canUndo`、`running`、`readOnly`

**验收步骤**：

1. `M` 新建（有/无工作区）、重命名（空/超长）、分叉各一次。
2. `M` 归档后 4s 内撤销：会话恢复且 Host 未收到归档。
3. `M` 运行中归档：出现停止确认与工作列表。
4. `M` 安全模式：操作被禁用并有原因。

### P1-14 模型、推理强度与权限预设

**场景**：用户切换模型、推理强度或权限模式。

**期望行为**：

- 顶栏模型胶囊显示当前模型与推理强度；点开选择器：搜索、能力标签、不可用项置灰并说明原因。
- 选择后以 Host 返回值为准回显；Host 校正/拒绝时提示，不显示未生效的值。
- 推理强度只列出该模型支持的档位；不支持时禁用。
- 权限预设显示当前值与影响（只读/工作区写/完全访问）；切换需风险确认，不静默改变。
- 选择结果对当前会话生效；新会话使用默认值；重启后保持（由 Host/本地设置决定，二者取一致来源）。
- 不允许通过原生页绕过审批或放宽沙箱；原生只调用官方选择接口。

**关键状态**：`model`、`effort`、`permissionPreset`、`saving`、`hostCorrected`

**验收步骤**：

1. `M` 切换模型/强度：胶囊与选择器一致，发一条消息确认实际模型。
2. `M` 选择不支持强度的模型：档位置灰。
3. `M` 切换权限：出现风险确认，取消后不改变。

### P1-15 SSH 主机表单与测试连接

**场景**：用户手动添加一台 SSH 主机。

**期望行为**：

- 字段：名称（默认=地址）、地址、端口（1–65535）、用户名、认证方式（密码/私钥+口令）、启动命令（默认值可改）、工作目录（可选）。
- 必填校验就地提示，保存时滚动到第一个错误；输入变化清除该字段错误。
- “测试连接”执行真实连接流程并显示阶段卡；测试结束关闭测试会话，但远端 DSH 保持运行。
- 首次连接弹出信任对话框：主机指纹、类型、核对命令、取消/信任并连接；指纹只在地址+端口不变时有效，改地址后需重新确认。
- 重置信任使用危险色二次确认，说明会削弱防冒充检查。
- 保存失败提示且不丢输入；有未保存修改时返回需确认。
- 密码/私钥/口令只存加密存储，不显示明文、不写日志。

**关键状态**：`config`、`errors{}`、`testStatus`、`hostKey(fingerprint, type, forAddress)`、`dirty`

**验收步骤**：

1. `M` 缺字段/非法端口/错误密码：就地错误、阶段卡失败、可重试。
2. `M` 首次连接：信任对话框指纹与远端命令输出一致；取消不保存。
3. `M` 修改地址后再连：要求重新确认指纹。
4. `M` 保存失败（只读存储/异常）：输入不丢。

### P1-16 远程断线与重连

**场景**：网络切换、远端进程退出、主机密钥变化、令牌过期。

**期望行为**：

- 连接状态四态：连接中/已连接/重连中/失败；阶段卡保留最近一次进度。
- 网络类错误自动指数退避重试；认证失败、指纹不匹配、远端缺 DSH 不自动重试，直接失败并给操作建议。
- 失败框：一句可行动摘要 + 可复制详情 + 重试；不把原始异常直接当标题。
- 断线期间保留会话列表、当前会话与草稿；回到前台自动重连。
- 主机密钥变化时拒绝连接并要求人工确认，不静默信任新密钥。
- 切换主机后聊天与会话列表跟随；切回本地不丢本地状态。
- 连接被替换、设备被撤销、令牌过期等有独立文案，不混为“网络错误”。

**关键状态**：`phase`、`step`、`errorKind`、`retryable`、`attempt`、`hostId`

**验收步骤**：

1. `M` 飞行模式 30s 再恢复：重连中→已连接，草稿不丢。
2. `M` 杀远端 DSH：失败并给出“启动 DSH”相关建议。
3. `M` 改远端主机密钥：拒绝并要求确认。
4. `M` 切换主机再切回：会话与草稿正确。

### P1-17 通知与点击定位

**场景**：应用在后台，会话完成、等待审批或等待回答。

**期望行为**：

- 通知区分“已完成/等待审批/等待回答”，带会话标题；同一会话合并，避免刷屏。
- 用户正在看的会话不发通知。
- 点击通知：冷启动与热启动都能打开对应会话；清除该会话未读与对应待处理标记。
- 目标会话加载失败时保留待处理目标，回退官方界面后继续完成同一目标，不静默吞掉。
- 通知内容不包含消息正文、密钥、路径等敏感信息（只显示标题与类型）。
- 通知权限被拒时有设置入口说明，不反复弹系统权限。

**关键状态**：`pendingTarget(sessionId, kind)`、`notifiedAt`、`foregroundSession`

**验收步骤**：

1. `M` 三种通知各触发一次：文案与合并正确。
2. `M` 点击冷启动/热启动：定位正确，未读清除。
3. `M` 目标会话被归档/删除：不崩溃，给回退提示。

## 7. P2 行为规格

### P2-01 公式、图表、HTML 折叠与 ANSI

- **场景**：回复含 `$...$`/`$$...$$`、Mermaid、`<details>`、终端 ANSI 输出。
- **期望**：行内/块级公式正确渲染，价格文本（`$5 和 $10`）不误判；Mermaid 渲染失败回退源码；`<details>/<summary>` 可折叠，未知 HTML 按文本；ANSI 颜色在工具输出中正确显示，不执行控制序列。
- **验收**：`M` 各构造一条；公式价格反例；Mermaid 错误语法；ANSI 彩色日志。

### P2-02 语音输入

- **场景**：用户用语音代替键盘。
- **期望**：草稿为空时发送键变麦克风；听写中显示识别文本、音量与停止；取消恢复原草稿；无权限/无模型给设置入口；识别失败不覆盖已输入文字。
- **验收**：`M` 权限拒绝、听写、取消、断网。

### P2-03 后台任务与子代理

- **场景**：一轮里启动后台任务或子代理，主会话继续。
- **期望**：后台任务以独立提示条显示状态与入口，不混入普通消息；子代理会话可从工具行打开；子代理结果回到主会话时标明来源；主会话不因后台任务阻塞输入。
- **验收**：`M` 启动后台任务/子代理，切换会话再回。

### P2-04 交付物卡片

- **场景**：一轮生成文件或显式交付。
- **期望**：轮次末尾显示交付物卡（文件名、类型、大小），点击预览；与“文件变更卡”区分（改动 vs 交付）；缺失文件给失败状态。
- **验收**：`M` 生成图片/文档/代码文件各一次。

### P2-05 用量与上下文

- **场景**：用户想知道本轮/本会话花了多少 token、上下文还剩多少。
- **期望**：每轮可展开用量（输入/输出/缓存命中）；会话统计入口；未知值显示“未知”而不是 0；不阻塞聊天。
- **验收**：`M` 完成一轮后查看；Host 不返回时显示未知。

### P2-06 分享与导出

- **场景**：分享单条回复或导出会话。
- **期望**：分享面板可复制文本/图片；导出不包含凭据；导出失败给原因；临时文件清理。
- **验收**：`M` 分享长回复、含代码回复；导出后用其他应用打开。

### P2-07 远程网络详情

- **场景**：用户排查远程连接质量。
- **期望**：显示路径（局域网/直连/中继）、往返时延、连接耗时、IP 版本；未知项不猜测；可复制诊断信息（脱敏）。
- **验收**：`M` 不同网络下查看；断开时显示未知。

### P2-08 会话多选批量操作

- **场景**：一次归档多个会话。
- **期望**：多选计数、全选/取消全选、批量归档一个撤销窗口、部分失败列出失败项并保留成功项。
- **验收**：`M` 批量归档 5 个，其中 1 个运行中。

### P2-09 引导与空状态

- **场景**：首次使用、无会话、无主机、服务未运行。
- **期望**：每个空状态说明“为什么空”和“下一步做什么”，给一个主操作；不显示假数据；服务未运行时区分“本机引擎”和“远程主机”。
- **验收**：`M` 清空数据后首次进入各页面。

## 9. 当前实现基线与差距

### 9.1 现状定位（只读核对，未跑产品测试）

| 能力 | 当前实现 | 规格条目 | 差距 |
|---|---|---|---|
| 增量合并 | `DshMuxProtocol` 按块序号累积 text-delta；`DshNativeController` 用 `streamingText` 覆盖式更新，正式消息到达后清空 | P0-01 | 无草稿行键、无重复/乱序丢弃、无重连快照合并；每帧直接改 Compose 状态，长回复有重组压力 |
| 流式 Markdown | `DshMarkdownParser` 未闭合围栏按“到末尾仍是代码”处理 | P0-02 | 无尾部修补，粗体/表格/链接在流式中会裸露或跳变；无揭示节奏与光标 |
| 列表跟随 | `DshNativePage` 的 `LazyColumn` 无 `LazyListState`，新内容不自动滚动 | P0-03 | 回复可能生成在屏幕外；无回到底部、无上翻保护 |
| 向前分页 | 读取最近 120 条，`hasMore` 只显示“更早历史请在官方界面查看” | P0-04 | 无 load older、无锚点补偿 |

| 失败 | 有整页错误 banner 与“重发上一条” | P0-07 | 无轮次内失败行、无错误码映射、无不支持模型的差异化操作 |

| 提问 | 仅识别 `user-questions/request` 并转交官方页 | P0-09 | 原生无提问卡，多题/多选/自填/草稿全部缺失 |
| 渲染 | 标题/段落/粗斜体/行内代码/列表/引用/分隔线/表格/图片占位/代码复制 | P1-01..04 | 无语法高亮、无图片加载、无链接打开、无任务列表/提示块/折叠 HTML/公式 |
| 消息操作 | 仅文本选择与代码复制 | P1-05 | 无整条复制、引用、编辑重发、分叉、重新回答 |

| 会话 | 独立会话管理页：新建/重命名/归档/搜索/模型/权限/目录 | P1-11..14 | 聊天页内仍是横向会话条；无按天分组/置顶/文件夹/多选；无待回答标记 |

### 9.2 建议切片顺序

1. **先补流式与列表骨架**（P0-01/02/03/04）：这是所有后续渲染与操作的地基；先用 JVM 夹具锁状态机，再做设备录屏。
2. **再补发送状态机与审批/提问**（P0-05/06/07/08/09）：涉及协议与安全闸门，必须与官方接口对齐后再改 UI。
3. **然后补阅读质量**（P1-01..04）与消息操作（P1-05）。
4. **最后补过程折叠、会话分组与远程引导**（P1-06..17）。

### 9.3 当前实现最大的三个差距

1. **流式没有“草稿行键 + 幂等合并”模型**：重复/乱序/重连会导致重复或丢字，且每帧覆盖式更新让长回复的重组成本不可控；这同时卡住 P0-02/03 的稳定性。
2. **列表没有跟随/锚定/分页**：回复可能长在屏幕外，用户上翻会被新内容推走，历史只能看 120 条；这是“看起来不能用”的首要原因。
3. **交互闸门不完整**：提问卡完全缺失，审批没有“本对话都允许”的确认与自动放行联动，失败没有轮次内可见行；用户在原生页遇到这些情况只能回官方页，核心闭环仍断。

## 10. 风险与开放问题

- **协议差异**：配对二次确认码依赖中继协议；Tanuki 当前契约是 `room/token/hostId/pin`，没有 8 位码。实现时应把“手机显示确认码、电脑端确认”映射为“指纹 + hostId 核对”，或先改 [INTERFACES](INTERFACES.md) 再实现，不能只为对齐 UI 而新增无协议支撑的假确认。
- **性能**：语法高亮、图片解码、长列表折叠都可能引入卡顿；P1 实现必须给大文本/大图/长会话上限与降级路径。
- **安全**：审批自动放行、链接外部打开、图片加载都扩大攻击面；任何放宽都必须有独立审查与设备验证。
- **可达性**：大字体、深色、读屏是验收项，不是“后续优化”；状态不能只靠颜色表达。
- **未验证**：本文所有设备步骤未执行；真实模型/账号、真机、远程 sshd、Keystore 仍受用户暂停项约束。
